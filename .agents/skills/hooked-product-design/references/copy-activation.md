# Copy for activation and action

These are original practical applications of chapters 1–3 and the autonomy discussion in chapter 4. Hooked is not a copywriting manual; examples below are not quotations or proven conversion formulas.

## Write the decision, not a behavioral-science explanation

For the current surface identify user state, need, expected outcome, one primary action, and required disclosure. Use the product's language and requested voice. Preserve established terminology. Explain a consequential choice at the moment it matters; defer optional detail behind a clearly labeled path.

A useful pattern is **recognizable need → concrete benefit → achievable next action**. Avoid generic motivation, feature lists without purpose, and neuroscience jargon. Text cannot solve unavailable value or excessive required steps; recommend a flow change when needed.

## Landing page and value proposition

| ID    | Surface         | Write/change                                   | Illustrative wording                                 | Check                                     |
| ----- | --------------- | ---------------------------------------------- | ---------------------------------------------------- | ----------------------------------------- |
| CA-01 | Main promise    | Name the desired result and relevant situation | Build your strategy with one short practice session  | Does the promise match delivered value?   |
| CA-02 | Supporting line | Explain how the first useful action works      | Try a guided challenge and see why each move matters | Can a newcomer predict the experience?    |
| CA-03 | Primary CTA     | Label the actual next action                   | Try a practice challenge                             | Does it open that task?                   |
| CA-04 | Secondary CTA   | Offer a distinct helpful alternative           | See how it works                                     | Does it reduce uncertainty?               |
| CA-05 | Benefits        | Tie capabilities to recurring user needs       | Resume where you left off                            | Is continuity implemented?                |
| CA-06 | Social proof    | Use genuine relevant evidence with context     | A verified user quotation, with permission           | Is it authentic and appropriately scoped? |

Do not invent session duration, prices, user counts, testimonials, rankings, or benefits. If unknown, omit or mark a placeholder for verification. A CTA promising a free trial must disclose conditions before commitment.

## Onboarding and progressive explanation

Introduce only what enables the current useful action. Reveal advanced modes after they become relevant. Explain required setup honestly; offer useful defaults where appropriate, with a visible alternative.

| ID    | Surface           | Pattern                                   | Illustrative wording                             |
| ----- | ----------------- | ----------------------------------------- | ------------------------------------------------ |
| CA-07 | Welcome           | Outcome plus first step                   | Start with a guided round                        |
| CA-08 | Experience choice | Ask only what changes the next experience | New to the game or ready for a challenge?        |
| CA-09 | Goal selection    | Let the user choose a meaningful aim      | What would you like to improve?                  |
| CA-10 | Mode explanation  | Explain result before mechanics           | Practice at your own pace. You can pause anytime |
| CA-11 | First instruction | One actionable step in context            | Select a piece to see its available moves        |
| CA-12 | Optional tutorial | Clear choice without penalty              | Show me the basics / Explore on my own           |
| CA-13 | Setup completion  | Name genuine readiness                    | Your practice plan is ready                      |
| CA-14 | Advanced option   | Show when relevant, with purpose          | Adjust the challenge level                       |

Examples assume those functions exist. Do not add tutorial steps simply to fit this table. Preserve essential rules, accessibility, and meaningful alternatives when simplifying.

## Empty states, forms, and authentication

| ID    | Surface                | What the text must do                           | Example                                                          |
| ----- | ---------------------- | ----------------------------------------------- | ---------------------------------------------------------------- |
| CA-15 | First-use empty state  | Explain purpose and one useful start            | Your saved challenges will appear here. Save one after trying it |
| CA-16 | No results             | State the outcome and recoverable action        | No matches for these filters. Try a broader search               |
| CA-17 | Cleared/completed list | Recognize actual completion                     | You're up to date. Add another item when you need it             |
| CA-18 | Field label/helper     | Ask for needed data and explain use             | Display name. This appears beside your public contributions      |
| CA-19 | Optional field         | Explicitly separate enrichment from requirement | Add an interest to tailor suggestions. Optional                  |
| CA-20 | Required setup         | Explain dependency and minimize scope           | Choose a level so we can select a suitable first challenge       |
| CA-21 | Account request        | Connect to actual account benefit               | Create an account to sync your saved work across devices         |
| CA-22 | Existing-user login    | Preserve the promised destination               | Sign in to continue this challenge                               |

Do not promise guest access, sync, or retained work if absent. If the product supports no useful option without registration, describe that constraint instead of labeling registration optional.

## Permissions and preference controls

Ask for permission in context, tied to experienced or imminent value. Separate a plan from the delivery channel. Give a real refusal path and explain how to change the decision later if supported.

| ID    | Surface                 | Example                                                         | Required behavioral truth                      |
| ----- | ----------------------- | --------------------------------------------------------------- | ---------------------------------------------- |
| CA-23 | Notification pre-prompt | Want a reminder at your chosen time?                            | A selectable schedule exists                   |
| CA-24 | Decline action          | Not now                                                         | Core use remains available as described        |
| CA-25 | Calendar/access request | Connect your calendar to suggest follow-up time after a meeting | Scope and use are correct; access is necessary |
| CA-26 | Public-sharing choice   | Share with the group / Keep private                             | Actual audience matches choice                 |
| CA-27 | Settings explanation    | Choose which updates you receive and when                       | Settings affect real delivery                  |

Avoid pressuring people to accept native permission dialogs or hiding refusal in low-contrast text. Relevant legal/product disclosures remain visible when required; progressive disclosure does not justify hiding consequential facts.

## Copy handoff

Provide placement, user state, proposed text, primary/secondary labels, click behavior, dynamic fields, locale, length constraints, accessibility semantics, and required functional changes. Call alternatives proposals unless tested. For a small request, deliver the final text and only the context needed to use it.

For later return messaging, read [lifecycle copy](copy-lifecycle.md). For results and recovery, read the relevant section of [feedback copy](copy-feedback.md).
