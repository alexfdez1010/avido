# Copy for rewards, investment, and recovery

Original applications of chapters 3–5. State handling, accessibility, and recovery patterns are practical extensions.

## Make the useful outcome visible

Feedback should show what happened, why it matters, and the user's available next choice. Do not substitute celebration for an actual result. Reflect authentic work and keep continuation optional when the useful unit is complete.

| ID    | Surface             | Write/change                                        | Illustrative wording                                                   |
| ----- | ------------------- | --------------------------------------------------- | ---------------------------------------------------------------------- |
| CF-01 | Completion          | Confirm actual useful result                        | Challenge complete. You identified the blocking move                   |
| CF-02 | Skill explanation   | Connect result to learning                          | This move protects both exits. Try spotting the same pattern next time |
| CF-03 | Missed attempt      | Explain recoverable cause without identity judgment | That leaves an open path. Review the position or try again             |
| CF-04 | Relevant discovery  | Name value, not empty surprise                      | A useful example for the tactic you practiced                          |
| CF-05 | Social feedback     | Attribute genuine useful response                   | Your answer helped someone resolve the question                        |
| CF-06 | Achievement         | Say what was earned and how                         | You completed three different practice themes                          |
| CF-07 | Satisfying endpoint | Allow stopping with completion                      | Today's practice is complete. Continue if you'd like                   |

Counts and interpretations require real data. Do not claim improvement from one result, fabricate praise, or promise learning without evaluating it. For learners, explain the task rather than labeling them smart, lazy, or deficient.

## Progress and streaks

Separate actual capability, completed work, calendar attendance, score, and reward currency. A streak is one representation of attendance, not the person's total progress. Describe any reset, freeze, or grace rule correctly; do not promise mechanics absent from the product.

| ID    | Surface                  | Draft pattern/example                                     | Truth to preserve                        |
| ----- | ------------------------ | --------------------------------------------------------- | ---------------------------------------- |
| CF-08 | Progress summary         | You've completed [count] exercises in [topic]             | Count/topic/window are accurate          |
| CF-09 | Next attainable step     | One more exercise completes this practice set             | Remaining work is real                   |
| CF-10 | Genuine initial progress | Your imported work is included. Choose the next step      | No fake progress for persuasion          |
| CF-11 | Missed-day state         | Your streak ended; your completed practice is still saved | Actual calendar and persistence rules    |
| CF-12 | Recovery option          | Start with a refresher                                    | Achievable restart; no required catch-up |
| CF-13 | Optional challenge       | Choose a weekly goal that fits your routine               | Actual cadence choice exists             |

Avoid warnings that the user will lose everything when only an attendance indicator changes. Progress indicators should describe the chosen goal, not constantly move the finish line to encourage more use.

## Investment requests

Ask for the smallest contribution that genuinely improves future usefulness, after value where possible. Explain the saved benefit and give an honest choice.

| ID    | Surface             | Example                                          | Future-value requirement                     |
| ----- | ------------------- | ------------------------------------------------ | -------------------------------------------- |
| CF-14 | Save result/item    | Save this example to review later                | Retrieval and persistence work               |
| CF-15 | Choose preference   | Choose a topic to tailor your next practice      | The choice actually changes suggestions      |
| CF-16 | Continue plan       | Add this to your practice plan                   | Next-use benefit is clear                    |
| CF-17 | Follow a real event | Follow this question for replies                 | Real event and separate channel choice       |
| CF-18 | Annotate            | Add a note for next time                         | Note remains accessible/editable             |
| CF-19 | Schedule cue        | Choose a reminder time / Skip reminders          | Core saved plan is not conditional on alerts |
| CF-20 | Confirmation        | Saved to [location]. Find it in [actual surface] | The named destination exists                 |
| CF-21 | Undo/change         | Undo save / Change topic                         | The action performs as labeled               |

Do not use setup-completion pressure to collect unnecessary fields. Avoid sunk-cost copy such as abandoning all that effort when the useful work can still be retained or exported.

## Errors, delay, interruption, and empty rewards

| ID    | State                    | Useful wording/action                                         | Behavioral requirement                      |
| ----- | ------------------------ | ------------------------------------------------------------- | ------------------------------------------- |
| CF-22 | Loading                  | Retrieving your saved progress                                | Describe actual operation; no fake urgency  |
| CF-23 | Slow result              | This is taking longer than expected. Try again                | Preserve work; avoid indefinite spinner     |
| CF-24 | Recoverable save failure | Your note wasn't saved. Retry or copy it before leaving       | Accurate retention state and recovery       |
| CF-25 | Offline                  | You're offline. [Supported action] is still available         | Do not promise unsupported offline behavior |
| CF-26 | Interrupted session      | Continue from your last saved step                            | Actual restore point is known               |
| CF-27 | No new content           | You're up to date. Revisit a saved example or come back later | Honest endpoint, no deceptive refresh bait  |
| CF-28 | No social reply          | No replies yet. You can edit the question or check later      | No invented activity                        |
| CF-29 | Unavailable deep link    | This item is unavailable. Choose another relevant item        | Useful fallback and explanation             |
| CF-30 | Exit/cancel              | Leave this session? [Actual saved/unsaved consequence]        | Make consequence precise; no shame          |

For destructive actions, explain what is actually lost. For benign exit, do not add unnecessary confirmation or emotional pressure. Announce important dynamic feedback accessibly and preserve sufficient reading time; do not rely on color, animation, or sound alone.

## Copy quality review

Verify accuracy, clarity of next action, locale consistency, dynamic data fallbacks, audience/privacy, accessibility, control behavior, and consistency between promised/actual state. Prefer a few materially different alternatives for tone/testing, then recommend one with a reason. Do not inflate the deliverable with many near-identical slogans.

Specify any missing functional behavior separately so implementation does not silently ship text that promises unsupported features.
